# Handoff, 2026-09-26 session

`main` (19e1b01) is the trusted firmware and is what is flashed on the ESP32 right now; it balances with an angle-only PID around a stored trim and creeps because that trim never exactly matches the true balance point. Branch `velocity-outer-loop` holds an attempt to fix the creep with a cascaded wheel-velocity PI loop (hoverboard RPM feedback → target pitch, integral acts as auto-trim, saved to flash on DISABLE), plus live gain persistence, a `MOTOR_TEST` wheel-pulse command, `tools/bb` helper, and `tools/smoke_test.py`; it was flashed and tested in pieces but destabilised the robot for two reasons that are now understood: the wheel feedback signs were left at +1/+1 for most of the session (mirrored motors cancel to ~0 so the integral wound up to its cap and pinned the target angle), and, more importantly, every ESP32 flash or reset done while the hoverboard was powered stalled the hoverboard's UART (EFeru's feedback is DMA-gated with no error recovery; symptom is 3 beeps and no feedback frames) which I repeatedly misdiagnosed as battery or wiring — the only recovery is a hoverboard power cycle after the ESP32 is up, and balancing must never be gated on that feedback. The verified hardware facts are: right-wheel RPM feedback is inverted (`MOTOR_TEST 80` reads L +25, R −31), feedback arrives at ~100 Hz when healthy, the hoverboard powers itself off after 8 min without a command above 50, the ESP32 accepts one Wi-Fi client and a dead client can hold that slot on `main`, opening the USB port resets the ESP32, and the laptop drops off `BizBot-Control` on every ESP32 reset (rejoining it from a script kills any process that was using the network, so do it by hand). Branch `tuner` is `main` plus only `tools/tuner` (Vite page + TCP bridge over Wi-Fi, same protocol as `keyboard_controls.py`, restricted to commands `main` supports), the `requirements.txt` fix (`pynput`, not `keyboard`), and README flashing notes; the Python tool is run with `.venv/bin/python tools/keyboard_controls.py --transport wifi`, PlatformIO is at `~/.platformio/penv/bin/pio`. If the velocity loop is picked up again, do it as one small change on top of `main`, verify each step against `main`'s behaviour on the real robot, and flash only with the hoverboard off.
